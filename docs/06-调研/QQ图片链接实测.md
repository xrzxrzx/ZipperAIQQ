# QQ 图片 / 表情包链接实测

> 日期：2026-10-25 · 问题记录 03 #2 · 服务器库（只读）

## 实测方法

从服务器 `Messages` 取最近 8 条含 `image` 段的消息，**立即**用 `urllib` GET（UA=Mozilla/5.0，不落盘）。

## 结果

| 1134 | `ACFEA1A30BB04866A25312E07694215B.jpg` | 200 | `image/jpeg` | `ffd8ffe0…` | 新图正常 |
| 1133 | `7C00BFDACD5B0C1C00227DAC1EB9D04E.jpg` | 200 | **`image/gif`** | `47494638…` | **扩展名 .jpg，实际 GIF** |

## 结论

1. **链接确实有时效**：刚收到的 200，隔一段时间的 400（带 `rkey` 的临时链接）。
2. **MIME 确实不能靠扩展名**：`.jpg` 实际是 `image/gif`；当前代码一律 `image/jpeg` → 上游按 JPEG 解析必然失败。
3. **必须"收到即取字节"**：只有在链接还有效时下载，才能在模型调用（可能延迟）时稳定读到。
4. 旧实现的两个问题都能解释"部分表情包读不到"，不是单一原因。

## 对应实现

- 入站消息到达时**预取**图片字节到内存缓存（TTL 30 分钟 / 64MB 上限）。
- 模型投喂前按魔数识别真实 MIME；GIF/WebP 用 SkiaSharp 取首帧转 PNG。
- 缓存未命中（如进程重启后翻历史）→ 重新尝试下载；失败 → `[图片：无法读取（链接可能已过期）]`。

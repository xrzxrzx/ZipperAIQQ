# ZipperAIQQ v0.5.2 · 黑名单修复（主人放行不再绕过）

> 发布日期：2026-10-29 · 基线：`v0.5.1` → `v0.5.2`
> 主题：**黑名单终于压过「主人自动放行」** —— 一个会让拉黑失效的判定顺序 bug

这是一个只修一个问题的补丁版：**群被加入黑名单后，机器人仍然回复**。

---

## 🐛 现象

- 在客户端「人员与名单 → 黑名单」里勾选了群，保存显示成功
- 但群里发消息，机器人**照样回复**
- 被拉黑的群同时出现在「主人放行（自动，不受名单影响）」列表里

## 🔍 根因

`ChatFilter` 的判定顺序是：

```
AlwaysAllow（主人私聊 + 主人所在的每个群） → Blacklist → Whitelist
```

而 `OwnerScopeResolver` 会把**主人所在的每一个群**自动写进 `AlwaysAllow`。
所以只要主人在那个群里，黑名单就永远轮不到 —— 这是判定顺序写反了，不是名单没保存。

## ✅ 修复

| 项 | 修复后 |
|---|---|
| 判定顺序 | **黑名单 → 主人放行 → 白名单**（显式拉黑优先于一切自动放行） |
| `OwnerScopeResolver` | 不再把已拉黑的私聊 / 群写进 `AlwaysAllow` |
| `ChatFilter` 写入 | 更新 `AlwaysAllow` 时剔除黑名单命中项，UI 不再显示"假放行" |
| 客户端文案 | 「主人放行（自动，不受名单影响）」→ **「主人放行（自动；黑名单优先）」** |

> ⚠️ 行为变化：如果主人**显式拉黑自己所在的群或自己的私聊**，现在会真的收不到消息。
> 这是黑名单的应有语义；要恢复的话把该条目从黑名单移除即可。

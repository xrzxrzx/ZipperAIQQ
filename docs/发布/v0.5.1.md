# ZipperAIQQ v0.5.1 · 代码卫生修复与稳定性补丁

> 发布日期：2026-10-28 · 基线：`v0.5.0` → `v0.5.1`
> 主题：僵尸代码清理 / 架构收口 / 文档一致性 + 一轮服务端与客户端缺陷修复

这一版没有新增功能，主线是**把 0.5.0 暴露出来的隐性缺陷修掉**，并清理长期积累的重复实现与死代码。
行为上最重要的三件事：**外部 WS token 不再明文落库/回显**、**清空的名单重启后不再复活**、**只写 YAML 也能启动**。

---

## 🐛 修复

### 启动与权限
- **只写 `config/server.yaml` 时服务起不来**：必需项校验移到 YAML 合并之后，不再先要求环境变量
- **清空管理员 / 白名单后重启会复活**：区分「显式写空」与「从未配置」，空列表也会应用到运行时
- 人设 `{"enabled": false}` 单独提交会被误拒（只切开关时正文沿用当前）
- 全局人设缺 `name` 时固定回退「小衣」→ 改为沿用现有名字

### 外部 WS / 抖音 / 邮件
- **外部 WS token 明文落库、`getExternal` 明文回显**：改为加密落库（`ISecretProtector`）、响应只回 `tokenConfigured`；旧明文 token 启动时自动迁移
- 抖音 token「显式清空」被启动配置复活；删除已废弃的 YAML `douyin.allowedSessions`（名单统一走 `ChatFilter`）
- 邮件管道在源启动失败后会永久停摆 → 单轮容错，下一轮继续重试
- 邮件摘要的 `MaxConcurrentSummaries` 实际未生效（串行）→ 按配置并发（写路径仍由 `ISqliteDatabase` 串行化）

### 服务端正确性
- `setBehavior` / `setConfig` 先写库后校验，失败会留下半套状态 → 全部校验通过后再统一写
- 缺 payload 或 payload 不是对象时返回 500 → 统一返回 400（dispatcher 归一化）
- 联系人查询失败被静默吞掉 → 补 Warning 日志（仍降级为空列表）
- `/ws/ext`、`/ws/channel` 的分块 token 使用非常量时间比较 → 改用 `CryptographicOperations.FixedTimeEquals`
- `/compact` 固定按 20 条压缩 → 使用运行时热窗
- 状态页 / `/status` 显示启动模型而不是热切换后的运行模型 → 读 `IChatClientProvider.CurrentModel`
- 平台 selfId 只写库不读 → 启动回灌到内存注册表（握手前也能正确判断 @）
- 外部 WS `hello` 缓存构造时的 selfId → 改为现读
- 出站队列无界、正向 WS 单帧无上限、网页抓取无响应上限 → 加 512 条 / 1MB / 4MB 上限
- 消息路由的会话缓冲区只增不删 → 空闲时精确摘除
- 主人反馈目标是全局单值 → 按平台键存储（`feedback.{platform}.*`，qq 镜像旧键）

### 客户端
- 3 个 `async void` 事件处理异常会直接崩进程 → 补兜底
- 登录轮询把 HTTP 超时当取消吞掉 → 只有真实取消才静默，超时按失败提示
- 二维码图片流每次换码泄漏 → 随换码/清码释放
- 审计页对单例 VM 的集合订阅未退订 → Loaded/Unloaded 成对管理
- 8 处裸 `catch` 补 `Debug.WriteLine` 留痕

## ⚠️ 契约变更（需要留意的唯一一处）

外部 WS 配置接口（`getExternal` / `setExternal`）：

| 字段 | 0.5.0 | 0.5.1 |
|---|---|---|
| `token` | 明文回显 | **移除** |
| `tokenConfigured` | — | 新增：只表示「是否已配置」 |
| `setExternal` 的 `token` | 空 = 不鉴权 | **三态**：不传 = 保持、`""` = 清除、非空 = 更新 |

仓库内的客户端已同步适配（留空不修改，勾选「清除已保存的 Token」才清除）。
**自定义外部 WS 客户端如果读了 `token` 字段，需要改读 `tokenConfigured`。**

## 🧹 质量与重构

- 删除确认无引用的僵尸代码：`TextTable`、ChatAgent 旧提示词常量、死成员 / 死配置 / 死 DTO、未使用依赖
- 客户端 DTO 从 1016 行拆成 8 个业务域文件
- `ServiceRegistration` 拆分：主文件 + Mail / Channels / Agent 三个 partial
- 新增 `MetricFacts`：命中率 / JEV / 降级口径只算一份（`/status` 与 `getStats` 共用）
- 新增 `OwnerService` / `NoticeSettings` / `IChannelLogin` / `SettingsValue` / `ContactDisplay` / `ClientDefaults`，收口多处重复实现
- 文档按代码事实校正：README / 架构说明 / 项目总览 / 架构方案 / 5 份早期设计文档加实现状态说明
- 测试：**348 → 373**（配置校验、外部 token、API 边界、命令目录、ChatAgent 历史窗口等）

## 🚀 升级提示

- **数据库 schema 无变更**，无需迁移
- 服务端首次启动会把外部 WS 的旧明文 token 迁移为密文（**需要原来的 Data Protection 密钥环** `/data/keys`；密钥环丢了仍会按既有逻辑回退/报错）
- `config/server.yaml` 无需改动；必需项现在也可以只写在 YAML 里
- 客户端与服务端建议**一起升级**（`getExternal` 字段变更；`ping` 的 `serverVersion` 变为 `0.5.1`）

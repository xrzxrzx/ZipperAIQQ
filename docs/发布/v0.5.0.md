# ZipperAIQQ v0.5.0 · 多平台接入（邮件 / 抖音）与运行时配置

> 发布日期：2026-10-28 · 基线：`v0.4.0` → `v0.5.0`
> 需求：[多平台通道接入](../01-需求/多平台通道接入-需求.md) · 设计：[多平台接入实施设计](../03-设计/多平台接入实施设计.md)

这一版的主线是**把「只有 QQ」变成一个能装多个平台的结构**，并把原本写死在 YAML 里的开关搬到客户端。
全程遵循"平台无关"的接缝：通道层只认 `IMessageChannel` / `IMessageSource`，上层不感知平台类型。

---

## ✨ 新增

### 多通道骨架
- `IMessageSource`（收信类平台）+ `CompositeMessageChannel`（多通道合并入站、按平台路由出站、故障隔离、能力并集）
- 发送节流仍在最外层：限的是"这个机器人说话多快"，与平台无关

### 邮件接入（IMAP）
- 收信 → 摘要（LLM）→ 汇总转发主人；网易系邮箱认证前先发 IMAP `ID` 命令
- 账号增删改、立即同步、凭据只回「已配置」（授权码加密落库，永不回显）
- **汇总先交人格 agent** 用当前人设转告主人；agent 没发出去才回落直发（不静默丢）
- 「汇总再经人格润色」可在客户端关掉（省一次模型调用）
- 支持 Outlook 收信的**现实路径**：Outlook 网页端自动转发到已支持的邮箱（OAuth2 方案见设计 §12，暂不实现）

### 抖音接入（sidecar + `/ws/channel`）
- 独立 Node sidecar（`douyin-sidecar/`）登录抖音、收发消息，通过 `/ws/channel` 与服务端双向通信
- 服务端侧：连接替换、ack 配对、长文本分段、联系人/群查询、平台专用工具
- **客户端可直接登录 / 退出 / 看二维码**（登录走 `login.start` → `login.qr`，退出只清登录态、sidecar 继续跑）
- 服务端主动心跳（25s），修掉"连上 90 秒就被 sidecar 判死"的假掉线

### 平台化配置
- 主人 / 管理员 / 白名单 / 黑名单 / 通知开关 / 工具权限**按平台各一套**（`access.{platform}.*`，含旧键回退）
- 会话白名单统一到「人员与名单」（`ChatFilter`，支持 `douyin:p*` 前缀通配）
- 新增「第三方平台接入」页：平台总览、邮件账号、抖音配置（含 token、超时、文本上限）、登录状态
- **运行时热切**：邮件接入 / 人格润色 / 抖音启用都改完即时生效，不必重启

### 消息查询跨平台
- 跨会话搜索结果每条带 `[平台:会话]` 来源；可只搜某个平台
- 提示词注入「你现在的平台」，并用角色解析判断"当前说话的人是谁"（主人 / 管理员 / 普通成员）

## 🐛 修复

- 客户端按钮/对话框主题不统一（显式 ControlTemplate + 可复用 `JpDialogStyle`，配色对齐 NapCat WebUI）
- `saveDouyin` 响应契约不一致（`saved` 是计数不是 bool）导致"配置存不上了"
- 抖音登录二维码拿不到（`qrcodeAt` 可空 + 先连 Server 再登录）
- 退出登录后仍显示已登录（清 `data/accounts` + 丢弃 douyin-im 客户端 + 服务端清 selfId）
- 163 水位卡死：网易系会重投旧 UID → 自行过滤并取最新一页；成功后清除 `LastError`
- 会话标题按平台显示（`抖音 · 拉链` 而不是 `douyin:p…` 原始 id）；卡片类消息降级为可读占位
- 新增 `purgeSession` 清理改 id 规则前遗留的僵尸会话

## ⚠️ 已知限制

- **抖音 `douyin-im` 的登录/发送/联系人 API 只做了有限真机验收**，未验收清单见[部署与登录指南 §8](../08-上手/抖音sidecar部署与登录.md)
- 邮件**只能收不能回**（回复要走邮箱自己的 SMTP，本期不做）
- 抖音群成员查询尚未验收 → 「主人放行」只保证主人私聊，群放行会降级
- 客户端页面只做了构建 + 生成代码绑定核对，未逐页真机点验

## 🚀 升级提示

- 抖音要单独部署 sidecar（Node ≥ 22.5），步骤见[部署与登录指南](../08-上手/抖音sidecar部署与登录.md)

## 第 9 项评估：MainViewModel 体量与拆分方案（2026-10-22）

### 结论：**过重，应拆**

现状 **615 行**，一个类里塞了 7 个职责：

| 职责 | 相关成员 | 行数占比（估） |
|---|---|---|
| 连接与设置 | ServerUrl / Token / StatusLine / Connect | ~10% |
| 状态页 | StatusText / RefreshStatus | ~5% |
| 会话页 | Sessions / Messages / SelectedSession / Load / Export | ~25% |
| 配置页 | ConfigText / ConfigName / BaseUrl / Model / Key / Save | ~15% |
| 运行参数 | Settings（SettingItem 集合）/ LoadSettings / SaveSettings | ~15% |
| 审计页 | Audits / LoadAudit | ~5% |
| 数据页 | Stats 及 8 个派生字符串 / LoadStats / ApplyStats | ~15% |
| 0.5s 心跳 | _timer / TickAsync / 三个 Refresh* | ~10% |

### 拆分方案（下一轮执行）

| 新类 | 内容 | 依赖 |
|---|---|---|
| `ConnectionViewModel` | ServerUrl / Token / StatusLine / ConnectCommand | ServerApiClient, AppSettings |
| `StatusViewModel` | StatusText / RefreshStatusCommand | 同上 |
| `SessionsViewModel` | Sessions / Messages / SelectedSession / Load / Export | 同上 |
| `ConfigViewModel` | 端点 + 运行参数（Settings 集合） | 同上 |
| `DataViewModel` | Stats + 派生字符串 + LoadStats | 同上 |
| `AuditViewModel` | Audits / LoadAudit | 同上 |
| `HeartbeatService` | 0.5s 定时器 + 按 CurrentPage 分频 | 各 VM |

页面改为各自 `App.Services.GetRequiredService<XxxViewModel>()`；
`StatusLine` 这类"全局状态条"可以留在 ConnectionViewModel，页面绑它。

**风险**：5 个页面的 `x:Bind Vm.XXX` 都要改（改属性名/类型），需要逐页编译验证。
**不做的理由（如不拆）**：项目只有 5 个页面；再涨到 8 个以上就一定要拆。

## 1. 范围与前置

### 1.1 本期做什么

| # | 内容 |
|---|---|
| 1 | **抖音私聊 + 群聊**的收发（含主动发送） |
| 2 | Node sidecar 与 Server 通过 **`/ws/channel`** 通信 |
| 3 | 断线重连、消息幂等、发送 ack 配对 |
| 4 | 文本 / 图片 / @ / 引用四种消息段 |
| 5 | 白名单（群 / 好友）与触发方式（@ / 自行判断）沿用现有机制 |

### 1.2 明确不做

- ❌ 评论区读写（`douyin-im` 不覆盖主站评论区，另案）
- ❌ 刷视频（非强制需求，另案）
- ❌ 表情收藏 / 视频消息 / 文件消息（第一版不做，能力矩阵后续扩展）
- ❌ 多账号（douyin-im 支持，但第一期先单账号）

### 1.3 前置事实

- `douyin-im` 是 **Node 22.5+ / ESM / `node:sqlite`**，.NET 无法直接调用 → **必须 sidecar**
- 消息事件结构：`type`（private/group/stranger）、`threadId`、`conversationShortId`、`senderUid`、`serverMessageId`、`text`、`content.kind`、`mentions`、`isMentionMe`、`referenceInfo`
- 出站：`sendText({ threadId, conversationShortId, text, mentions })` 或 `sendMessage(...)`；文本 **≤ 16000 字符**
- 发送前有 `conversation-risk` 检查，命中会拒绝 → 必须回填失败原因
- 现有 `/ws/ext` 是**旁路**（看/代发），缺"入站注入"方向 → 新建 `/ws/channel`

## 2. 总体设计

### 2.1 拓扑

```
┌─ Node sidecar（独立进程，Node 22.5+）─────────────┐
│  douyin-im（登录 / 事件 / 发送 / 断线补拉）        │
│  登录态 data/（**必须备份**，含 Cookie/设备身份）  │
└──────────────────┬───────────────────────────────┘
                   │ WS 连入（sidecar 主动重连）
                   ▼
┌─ ZipperAIQQ.Server ──────────────────────────────┐
│  /ws/channel（Kestrel 端点，Bearer token）        │
│        │ AttachAsync                             │
│        ▼                                         │
│  DouyinChannel : IMessageChannel                 │
│    ReceiveAsync ← 内部 Channel<InboundEvent>     │
│    SendAsync    → WS outbound 帧                 │
└──────────────────────────────────────────────────┘
```

### 2.2 为什么是「反向连接」

- Server 常驻，sidecar 可能重启 → **sidecar 主动连入**，断了自动重连
- 不用 Server 去连 sidecar，省掉 sidecar 开监听端口与端口分配

### 2.3 `DouyinChannel` 的职责

```csharp
public sealed class DouyinChannel : IMessageChannel
{
    public string Platform => "douyin";
    public string? SelfId { get; private set; }        // 由 hello 帧更新
    public ChannelCapabilities Capabilities => Text | Image | Mention | Reply;

    Task StartAsync(CancellationToken ct);              // 空实现（等 sidecar 连入）
    IAsyncEnumerable<InboundEvent> ReceiveAsync(CancellationToken ct);
    Task SendAsync(OutgoingMessage message, CancellationToken ct);
}
```

关键点：

- **连接可替换**：sidecar 重连时新连接替换旧连接，`ReceiveAsync` 不中断（内部 `Channel<InboundEvent>` 缓冲）
- **发送失败要抛出**（对齐 `IMessageChannel` 约定，让上层回填给模型）
- **`SelfId` 由 hello 帧驱动**，`SelfIdChanged` 事件通知持久化

## 3. 协议（`/ws/channel`）

### 3.1 帧形状

复用 `ExternalProtocol` 的 `{type, time, data}`（与 `/ws/ext` 同风格，但**语义不同、端点不同**）。

### 3.2 方向与类型

| 方向 | type | 说明 |
|---|---|---|
| sidecar → Server | `hello` | 握手：协议版本、selfId、能力 |
| sidecar → Server | `inbound` | 一条入站消息 |
| Server → sidecar | `outbound` | 一条出站消息（带 requestId） |
| sidecar → Server | `ack` | 出站结果（requestId 配对） |
| Server → sidecar | `query.contacts` | 查询好友 / 可私信对象（供「人员与名单」选人） |
| Server → sidecar | `query.groups` | 查询群列表（供「人员与名单」选群） |
| sidecar → Server | `result` | 查询结果（requestId 配对） |
| Server → sidecar | `ping` / sidecar → Server `pong` | 心跳（可选，MVP 用 WS 层 ping） |

### 3.3 示例

```jsonc
// hello
{"type":"hello","time":0,"data":{"version":"1","platform":"douyin","selfId":"<uid>","capabilities":["text","image","mention","reply"]}}

// inbound
{"type":"inbound","time":0,"data":{
  "session":"douyin:g123",          // Server 侧 SessionId（带平台前缀）
  "chatType":"group",               // private | group
  "messageId":"<serverMessageId>",
  "sender":{"userId":"<uid>","nickname":"<nick>","displayName":"<name>"},
  "segments":[{"type":"text","text":"hi"},{"type":"mention","userId":"<uid>"}],
  "replyTo":"<serverMessageId>",    // 可选
  "time":1730000000000
}}

// outbound
{"type":"outbound","time":0,"data":{
  "session":"douyin:g123",
  "segments":[{"type":"text","text":"你好"}],
  "replyTo":"<serverMessageId>",    // 可选
  "requestId":"<uuid>"
}}

// ack
{"type":"ack","time":0,"data":{"requestId":"<uuid>","ok":true,"error":null}}
```

### 3.4 幂等与顺序

- **入站去重**：Server 侧按 `(Platform="douyin", messageId)` 查库预检；重复直接丢弃（记 Debug）。落库唯一索引 `UX_Messages_Platform_MessageId` 兜底——现有 `InsertSql` 是**普通 INSERT**，撞索引会抛异常，所以**预检不能省**
- **出站配对**：`requestId` → `TaskCompletionSource`，超时（默认 15s）清理 pending，**不泄漏**
- **顺序**：同一 `session` 的消息按到达顺序入 `Channel<InboundEvent>`（单 reader），与现有 `MessageRouter` 的会话缓冲配合

### 3.5 候选查询（供「人员与名单」）

抖音的「人员与名单」需要好友 / 群候选（与 QQ 的 `IContactDirectory` 对齐）：

| 请求 | sidecar 实现 | 返回 |
|---|---|---|
| `query.contacts` | `account.getFriendList()` | `[{userId, nickname, remark?}]` |
| `query.groups` | `account.getGroupList()` | `[{groupId, name, memberCount?}]` |

- 与 `outbound` 一样用 `requestId` 配对，超时（默认 10s）返回错误
- **候选取不到时不阻塞**：返回空列表 + 错误原因，客户端显示「抖音未连接」而不是假装没有好友
- 候选**不落库**（瞬时数据），除非将来要做联系人缓存

## 4. 消息映射

### 4.1 入站（douyin-im → Server）

| douyin-im | Server |
|---|---|
| `type = message.private` | `ChatRef { Platform="douyin", Type=Private, Id=threadId }` |
| `type = message.group` | `ChatRef { Platform="douyin", Type=Group, Id=threadId }` |
| `type = message.stranger` | 第一版**丢弃**（陌生人盒不响应，记 Debug） |
| `senderUid` / 昵称 | `SenderInfo.UserId` / `Nickname` |
| `content.kind = text` | `TextSegment` |
| `content.kind = image` | `ImageSegment(url)` |
| `mentions[]` | `MentionSegment(uid)` |
| `referenceInfo` | `ReplySegment(serverMessageId)` |
| `serverMessageId` | `InboundEvent.EventId` |
| 平台时间戳 | `OccurredAt`（**不取 UtcNow**） |
| `content.kind = video/emoji/file/...` | 降级为 `TextSegment("[视频]")` 等占位（第一版） |

### 4.2 出站（Server → douyin-im）

| Server | douyin-im |
|---|---|
| `TextSegment` | 文本（超 16000 字符**自动分段**，按现有长文本切分逻辑） |
| `MentionSegment` | `segment.at(uid, name)` → `mentions[]` |
| `ImageSegment(url)` | sidecar 下载 URL → `uploadImage` → `segment.image` |
| `ReplySegment(id)` | `segment.reply({ referencedMessageId: id, ... })` |

> 图片由 **sidecar 负责下载与上传**（Server 只传 URL），避免服务端承担媒体下载。

## 5. 多通道与路由（依赖决策三）

抖音是**第二个 `IMessageChannel`**，必须与 NapCat 并存：

```
CompositeMessageChannel
  ├─ NapCatChannel（IMessageChannel，QQ）
  └─ DouyinChannel（IMessageChannel，本方案）
```

- `MessageRouter` 从「消费单个通道」改为「消费复合通道」
- 出站按 `ChatRef.Platform` 路由（`qq` → NapCat，`douyin` → DouyinChannel）
- 邮件是 `IMessageSource`（只收），也并入复合通道的入站侧

> ⚠️ **依赖顺序**：本方案必须在决策三骨架（`CompositeMessageChannel`）之后实施；单独先做抖音会逼出一个临时单通道方案，后面返工。

## 6. 配置与鉴权

### 6.1 配置（`appsettings.json` 的 `douyin` 节）

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | false | 总开关 |
| `token` | （必填，enabled 时） | `/ws/channel` 的 Bearer token |
| `allowedSessions` | 空=全部 | 白名单（`douyin:p*` / `douyin:g*`，支持 `*` 后缀） |
| `sendTimeoutMs` | 15000 | 出站 ack 超时 |
| `maxTextLength` | 16000 | 超长分段阈值（与 douyin-im 对齐） |

### 6.2 鉴权

- 复用 `HttpAccessPolicy`：loopback 免验；非 loopback 强制 token
- 每块 token（与 `ExternalReverseServer` 同口径）
- **token 不落日志、不回显**

### 6.3 sidecar 配置（`douyin-sidecar/config.json`）

| 键 | 说明 |
|---|---|
| `serverUrl` | `ws://127.0.0.1:<port>/ws/channel` |
| `token` | 与 Server 配置一致 |
| `dataDir` | 登录态目录（**不入库、必须备份**） |
| `account` | 单账号；登录方式由 douyin-im 交互决定 |

### 6.4 平台配套（决策五 / 六 / 七）

| 决策 | 抖音侧落地 |
|---|---|
| 五：工具适配 | 抖音专用 API 工具注册进 `IToolRegistry` 并出现在客户端「工具配置」；QQ 专用工具（戳一戳 / 表情 / 语音）对抖音不可见 |
| 六：通知口径 | 抖音通知（好友申请、入群申请、成员变化、会话同步）进「运行与行为」的抖音分组 |
| 七：配置页 | 「第三方平台接入」页的「抖音」Tab：sidecar 地址 / token / 登录状态 / 白名单，数据块 UI（参考 `ExternalPage`） |

## 8. 验收标准

| # | 标准 | 判定 |
|---|---|---|
| 1 | sidecar 连上 `/ws/channel`，私聊/群消息能进 AI 并回复 | 真机收发 |

| 8 | `data/` 不在仓库、不被提交 | `git status` + `.gitignore` |

## 10. 风险与未决

| # | 风险/未决 | 影响 | 缓解 |
|---|---|---|---|

### 11.2 实现选择（原稿没写死、由实现定的）

| 项 | 结论 | 风险 |
|---|---|---|
| **入站帧形状** | 两种都收：§4.1 的**原生** `douyin-im` 事件形状 + §3.3 的**已翻译**形状（`session` + `segments[]`） | 最大的一条假设 —— sidecar 实际发哪种要联调确认 |
| **token 传递** | `?token=`（query） | Node 全局 `WebSocket` 不支持自定义 header；侧车改 header 只需动一处 |
| `result` 载荷 | `{requestId, ok, error, contacts|groups}` | 设计只给了类型没给字段 |
| **引用回复** | `replyTo` 放**帧级**，且只跟首帧 | §4.2 写的是段级 `segment.reply(...)`；sidecar 若只认段级要改 |
| 长文本 | 按 `MaxTextLength`（16000 字符）**分帧发**，不截断；不切代理对 | — |
| 账号级 `selfId` | 由 `hello` 驱动；持久化到 `bot.selfId:{platform}`（旧键 `bot.selfId` 继续写 QQ 的值） | — |
| 通道不做落库/去重 | 去重靠 `Messages` 唯一索引 + 路由层预检 | 与 §3.4 一致 |

4. `sendText({threadId, conversationShortId, text, mentions})` / `sendMessage(...)` / `uploadImage()`
5. `getFriendList()` / `getGroupList()`
6. 登录验证 URL 的字段名（`verifyUrl` / `url` / 二维码）

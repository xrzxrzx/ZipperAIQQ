# 记忆图谱设计（R-09，L 批）

> 状态：**评估后暂缓（2026-11-06）**。实测 1638 条线上向量：向量 top-5 邻居 63% 同会话、
> 37% 跨会话，且热窗只覆盖 27% —— 真正缺口是**跨会话召回**，不是图。
> 已改为「跨会话向量召回 + 混合打分」（`recall_related`）；图（L-1~L-4）等有「记忆点」层后再评估。
> 关联：`docs/01-需求/运行可靠性与会话交互-需求.md` R-09；
> 现有实现：消息级向量检索（`MemoryRetriever` / `SqliteEmbeddingStore`），**没有边**。

## 1. 拍板结论

| 问题 | 结论 |
|---|---|
| 存储形态 | **双写**：Markdown 文件是**真源**（人可编辑），SQLite 只做**索引缓存** |
| 「注意力」 | **检索打分**：向量 top-k → 沿边扩散重排（RAG + 图扩散），不训练 attention 层 |
| 规模 | 百~千级；**时间衰减 + 访问次数**控制膨胀 |
| 边的来源 | **自动 + 手动**都支持：相似度自动建边、模型/人工显式链接 |

## 2. 文件形态（真源）

```
memory/
  nodes/
    2026-11-06-拉链的偏好-3f2a.md
    2026-10-30-关于抖音接入-9c1b.md
  index/            ← 可选：导出视图（只读，由系统生成）
```

单个节点的 Markdown：

```markdown
---
id: 3f2a9c1b
title: 拉链的偏好
tags: [主人, 偏好]
created: 2026-11-06T10:00:00+08:00
updated: 2026-11-06T10:00:00+08:00
---

拉链喜欢先看证据再下结论，讨厌空话。

相关：[[9c1b0a77]]（抖音接入讨论）、[[话题/作息]]
```

- `id`：8 位十六进制，文件名与 front matter 一致；改名不改 id。
- 链接语法 `[[id]]` 或 `[[title]]`：解析时先按 id 匹配，再按标题回退。
- 文件被外部编辑（Obsidian / 编辑器）→ 索引器按 `mtime + 内容哈希` 增量重建，**不覆盖用户内容**。

## 3. 索引缓存（SQLite，schema v19）

```sql
MemoryNodes (
  Id TEXT PRIMARY KEY,
  Path TEXT NOT NULL,
  Title TEXT NOT NULL,
  Tags TEXT,              -- JSON 数组
  ContentHash TEXT NOT NULL,
  UpdatedAtMs INTEGER NOT NULL,
  LastAccessedAtMs INTEGER,
  AccessCount INTEGER NOT NULL DEFAULT 0
);

MemoryEdges (
  FromId TEXT NOT NULL,
  ToId TEXT NOT NULL,
  Kind TEXT NOT NULL,     -- manual | auto
  Weight REAL NOT NULL,   -- 0..1
  UpdatedAtMs INTEGER NOT NULL,
  PRIMARY KEY (FromId, ToId, Kind)
);

MemoryNodeVectors (
  NodeId TEXT PRIMARY KEY,
  Vector BLOB NOT NULL,
  Model TEXT NOT NULL,
  UpdatedAtMs INTEGER NOT NULL
);
```

**缓存可随时删除**：删掉 `MemoryNodes/Edges/Vectors` 后，索引器扫描 `memory/nodes/*.md` 全量重建。

## 4. 检索与打分（「注意力」）

```
query 向量
  → 候选：向量 top-k（k=20，复用现有 embedding 模型）
  → 扩散：候选的一度邻居（manual 边权重 1.0，auto 边 0.6）
  → 重排：score = 0.7*sim + 0.3*neighborBoost
  → 衰减：score *= exp(-ageDays / halfLife)，halfLife 默认 30 天
  → 取前 N（默认 6）
```

- 一度扩散就够：两度会把「八竿子打不着」的内容拖进来（L-3 再评估）。
- 衰减只作用于**检索排序**，不删除文件；访问过（AccessCount/LastAccessed）会轻微加权。
- 命中结果必须带**链接理由**：`来自 [[拉链的偏好]] 的手动链接` / `与 X 相似度 0.83`。

## 5. 边的产生

| 来源 | 时机 | 权重 |
|---|---|---|
| 手动（`[[...]]`） | 索引器解析 Markdown | 1.0 |
| 模型 | 新工具 `memory_link(fromId, toId, reason)`（管理员） | 0.9 |
| 自动 | 写入/重建索引时，与已有节点相似度 ≥ 0.82 | 0.6（相似度×0.8 上限） |

- 自动边数量上限：每个节点最多 8 条，按相似度取前 8 —— 防止「全连接」让扩散失效。
- 衰减：边 90 天未被任何一次检索命中 → 降权 50%；再 90 天未被命中 → 删除（仅 auto，manual 永不自动删）。

---

## 6. 与现有检索的关系

- **不替换**现有消息检索：消息仍是「对话流水」，记忆节点是「提炼后的知识」。
- 记忆工具先给模型用（`memory_search` 带图扩散、`memory_link` 建边）；确认有效后，再考虑把节点写入接到「收轮/提炼」流程（另排期）。

## 7. 分阶段实施

| 步 | 内容 | 验收 |
|---|---|---|
| L-1 | 文件格式 + 索引器（扫描/解析/建边/缓存）+ `MemoryNodes/Edges` 表 | 手改 md 后 1 次重建即生效；删缓存可全量重建 |
| L-2 | 向量化 + 一度扩散 + 打分（含衰减）+ `memory_search` 工具 | 固定 query 下，图扩散结果优于纯 top-k（同一批样本） |
| L-3 | 固定测试集对照（图 vs top-k） | 召回率/相关度有数字对比，不靠感觉 |
| L-4 | 自动建边策略、衰减与淘汰 | 库不再单调膨胀；边数量有上限 |

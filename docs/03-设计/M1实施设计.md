## 2. 目标项目结构（M1）

```
ZipperAIQQ.slnx
├── ZipperAIQQ.Core            横切：配置 / 日志 / 事件总线        [已有]
├── ZipperAIQQ.Transport       字节层：WebSocket 双端复用          [已有]
├── ZipperAIQQ.Channel         语义层：平台无关消息模型 + 收发       [新增]
├── ZipperAIQQ.Agent           AI：会话实例 / 工具 / 上下文         [新增]
├── ZipperAIQQ.Storage         持久化：SQLite / 消息 / 会话 / 日志   [新增]
└── ZipperAIQQ.Server          组合根：宿主 / HTTP / WS / 编排      [新增]
```

**依赖方向（单向，不许反向）**：

```
Server ──► Agent ──► Core
   │         │
   ├──► Channel ──► Transport ──► Core
   └──► Storage ──► Core
```

- `Core` 不依赖任何内部项目
- `Transport` / `Channel` / `Agent` / `Storage` **互不依赖**（Server 负责把它们缝起来）
- **`Channel` 不引用 `Agent`** —— 通道只收发，不做决策
- **M2 才会出现**：`ZipperAIQQ.Scheduler`（或并入 Server）、`ZipperAIQQ.Client`（WinUI3）

## 4. 关键接口定义

### 4.1 通道抽象（接缝 B）

```csharp
public interface IMessageChannel
{
    string Platform { get; }                    // "qq"
    ChannelCapabilities Capabilities { get; }
    IAsyncEnumerable<IncomingMessage> ReceiveAsync(CancellationToken ct);
    Task SendAsync(OutgoingMessage message, CancellationToken ct);
}

public sealed record IncomingMessage
{
    public required ChatRef Chat { get; init; }
    public required SenderInfo Sender { get; init; }
    public required IReadOnlyList<MessageSegment> Segments { get; init; }
    public required DateTimeOffset SentAt { get; init; }   // 平台时间戳，不重取
    public string? ReplyToMessageId { get; init; }
}

public sealed record SenderInfo
{
    public required string UserId { get; init; }
    public string? GroupCard { get; init; }     // 群昵称（可空）
    public string? Nickname { get; init; }      // QQ 昵称（可空）
    public bool IsFriend { get; init; }

    /// 双名并列 —— FR-13.2
    public string DisplayName =>
        GroupCard is null ? (Nickname ?? UserId)
        : Nickname is null ? GroupCard
        : $"{GroupCard}（{Nickname}）";
}
```

### 4.2 会话实例（D9：一聊天一 agent）

```csharp
public interface IChatAgent
{
    string SessionId { get; }
    DateTimeOffset LastActiveAt { get; }
    IAsyncEnumerable<AgentEvent> RunAsync(AgentRunRequest request, CancellationToken ct);
}

public interface IChatAgentPool
{
    /// 取实例；不存在则从 Storage 重建（FR-3.7 行为等价）
    ValueTask<IChatAgent> GetAsync(string sessionId, CancellationToken ct);
    /// 冷热管理：卸载最久未活跃的实例
    ValueTask UnloadAsync(string sessionId);
    int LoadedCount { get; }
}
```

**并发纪律**：同一个 `IChatAgent` 内部串行（实例内一把锁）；不同会话**并行**。

### 4.5 机密保护（FR-8.6~8.9）

```csharp
public interface ISecretProtector
{
    string Protect(string plaintext);       // → Base64 密文
    string? Unprotect(string ciphertext);   // 解不开返回 null（不抛）
}

public interface ISecretStore
{
    ValueTask<string?> GetAsync(string key, CancellationToken ct);
    ValueTask SetAsync(string key, string plaintext, CancellationToken ct);
    /// 只返回掩码，永不返回明文： "sk-****a1b2"
    ValueTask<string?> GetMaskedAsync(string key, CancellationToken ct);
}
```

**三条硬约束**：

1. `AgentOptions.ApiKey` 标 `[JsonIgnore]` —— **绝不经 `ZipperConfig.Save()` 落盘**
2. 加密用 `IDataProtector`（ASP.NET Core Data Protection），**不自己写密码学**
3. **API 响应里永不出现明文** —— 只有掩码

### 4.7 多模型端点（FR-8.10 ~ 8.12）

```csharp
public enum LlmApiKind
{
    Responses,        // OpenAI Responses API —— DeepSeek
    ChatCompletions,  // OpenAI Chat Completions —— OpenRouter（JEV）
}

public sealed record LlmEndpointOptions
{
    public required string Name { get; init; }      // "deepseek" / "jev"
    public required string BaseUrl { get; init; }
    public required string Model { get; init; }
    public required LlmApiKind ApiKind { get; init; }
    // ⚠️ 这里没有 Key —— 由 ISecretStore 按 Name 单独加密存取
}

public interface ILlmClientRegistry
{
    /// 按角色取客户端：Chat = 主模型，Judge = JEV
    IChatClient GetFor(LlmRole role);
    /// 按名称取（工具 / 调试用）
    bool TryGet(string endpointName, out IChatClient client);
}

public enum LlmRole { Chat, Judge }
```

**⭐ 为什么 `ApiKind` 必须显式配**：两个端点的 API 形态**不一样** —— DeepSeek 走 **Responses API**（`GetResponsesClient`），OpenRouter 主要兼容 **Chat Completions**（`GetChatClient`）。写死一种，另一个直接不可用。

**配置形态**：

```json
{
  "Llm": {
    "Endpoints": {
      "deepseek": {
        "BaseUrl": "https://api.deepseek.com",
        "Model": "deepseek-flash",
        "ApiKind": "Responses"
      },
      "jev": {
        "BaseUrl": "https://openrouter.ai/api/v1",
        "Model": "typesafe/jev-1.13",
        "ApiKind": "ChatCompletions"
      }
    },
    "Roles": { "Chat": "deepseek", "Judge": "jev" }
  }
}
```

**M1 只落结构、不启用 JEV**：`Roles.Judge` 为空时，所有判断走规则（FR-4 的 L3）。这样 M2 开 JEV 不需要改数据结构。

**⚠️ 可配置性硬约束（FR-8.13）**：

| 约束 | 验收方式 |
|---|---|
| 代码里**不出现任何平台 URL / 模型名字面量** | `grep -r "api\.deepseek\.com\|openrouter\.ai\|deepseek-flash\|typesafe/jev" ZipperAIQQ.*/`（排除 obj）**必须为空** |
| **端点数量不固定** | 配置里加第三个端点 → **不需要改一行代码** |
| 缺失必需端点 | 启动 **fail-fast**，错误信息说清「缺哪个角色的端点」 |
| **不提供内置默认值** | 默认值只放 `appsettings.Example.json`，代码只负责「读不到就报错」 |

> 「示例配置」负责告诉用户该填什么；**代码只负责读不到就报错**。内置默认值本质上就是软性硬编码 —— 表面可配，实际没人改得动。

## 6. 测试策略

| 层 | 用什么 | 约束 |
|---|---|---|
| **单元** | xUnit + 假 `IChatClient` / 假 `IClock` | **不打真实 DeepSeek** |
| **集成** | 内存 SQLite（`:memory:`） | 不碰真实数据库文件 |
| **契约** | `docs/05-契约/*.json` 断言 | 报文结构变更必须先改样例 |
| **端到端** | NapCat 真实实例 | **仅手动**，不进 CI |

**必须有的测试**（缺一个就是静默失效）：

1. 兜底发送（模型不调工具）
2. 压缩后 system 未丢
3. 实例卸载重建后上下文等价
4. 路径穿越被拦截（M2）
5. 未加密的 key **不出现在** `config.json`
6. **分词器**：已知句子 → 预期 token 序列。**分词错了不会报错，只会让检索悄悄变差**，这是最典型的静默失效
7. **向量维度**：实测维度 == 表结构里声明的维度（不一致时建索引就会炸）

> **6 与 7 的理由**：向量检索这条链上，错误**全部表现成「效果差一点」而不是异常**。
> 所以它必须靠**断言**兜住，不能靠"看起来还行"。

|---|---|---|
| **M1-A** | Core（改动）+ Channel + Storage（**统一 DB 入口** + 消息表） | 收到真实 QQ 消息并入库 |
| **M1-B** | Agent（最小）+ Server（组合根）+ Responses API | 私聊一问一答 |
| **M1-C** | Agent（上下文 / 预取 / 检索）+ Storage（FTS5 + 向量） | 压缩不丢人设，历史答得上 |
| **M1-D** | Agent（人设 / 重注入） | 连聊 30 轮不崩 |
| **M1-E** | Agent（权限门禁 + 文件工具）+ 工作区沙箱 | 文件增删改查可用，**越权与路径穿越被拦** |
| **M1-F** | Scheduler（表 + 轮询 + CRUD 工具） | 定时发一条消息；**其次，不阻塞 E** |

> **顺序的先决条件**：M1-A 依赖 Transport 的 `Attach` 可用（见 [`进度.md`](../07-记忆/进度.md) 的 T2）。
>
> **M1-E 为什么排在人设之后**：文件工具能改东西，一旦权限门禁有漏洞后果不可逆（**没有 undo**）。
> 先把「AI 的行为」调顺（M1-B~D），再给它「动手的能力」（M1-E）。
>
> **⚠️ M1-E 的安全前提**：`file_delete` 与跨会话读写**默认仅管理员**；门禁校验的是**解析后的真实路径**，不是原始入参。

# 部署指南 · Windows 家用服务器

> 目标：把服务端部署到一台 Windows 机器上，并且**能像 Linux 上那样"先停 → 再改 → 再拉起"**。
>
> ⚠️ 本文所有主机地址、账号、token、密钥一律用占位符（`<server-ip>` 这类），
> 真实值只在本地脚本/配置里，**不入库**。

---

## 一、部署形态

| 项 | 值 |
|---|---|
| 目标机 | Windows 10/11 或 Windows Server（<server-ip>） |
| 目标目录 | `D:\App\ZipperAIQQ` |
| 运行方式 | **计划任务**（SYSTEM 账户 + 开机自启） |
| 进程 | `ZipperAIQQ.Server.exe`（self-contained，目标机**无需装 .NET**） |
| 配置文件 | `config\server.yaml`（YAML 优先于环境变量） |
| 日志 | `stdout.log` / `stderr.log` / `logs\zipper-<date>.log` |

### 为什么用计划任务，不用 Windows 服务

| 方案 | 结果 |
|---|---|
| `sc.exe create` | ❌ **1053**（服务未及时响应）—— `.exe` 是控制台程序，不实现 SCM 协议 |
| `Start-Process`（经 SSH） | ❌ 进程**随 SSH 会话结束被清理**（Windows OpenSSH 的会话隔离） |
| `schtasks /run`（SYSTEM 账户） | ✅ 脱离会话、开机自启、`/end` + `taskkill` 可停 |

## 二、前置条件

### 1. SSH 免密（用于传输与远程启停）

```powershell
# 若还没有 key
ssh-keygen -t ed25519

# 管理员账号的 key 要放进 administrators_authorized_keys（不是用户目录）
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh <ssh-user>@<server-ip> `
    "Add-Content C:\ProgramData\ssh\administrators_authorized_keys `$_"
```

> **坑**：Windows OpenSSH 对**管理员账号**只认
> `C:\ProgramData\ssh\administrators_authorized_keys`，而且该文件**权限必须严格**
> （仅 Administrators + SYSTEM）。放错位置或权限过宽都会静默拒绝。
>
> 验证：`ssh <ssh-user>@<server-ip> "echo OK"` 应直接返回 `OK`（不提示密码）。

### 2. SSH 的默认 shell 是 PowerShell

远程执行命令用 **PowerShell 语法**（不是 cmd）：

```powershell
ssh <ssh-user>@<server-ip> "Test-Path 'D:\App\ZipperAIQQ'"
```

### 3. 目标机没有 tar

Windows Server 未必带 `tar.exe`，所以部署脚本用 **`scp -r`** 传文件（不依赖远端工具）。

## 三、首次部署（只需做一次）

```powershell
# ① 建目录
ssh <ssh-user>@<server-ip> "New-Item -ItemType Directory -Force -Path 'D:\App\ZipperAIQQ\temp\bge-small-zh-v1.5','D:\App\ZipperAIQQ\config' | Out-Null"

# ② 发布 + 传主程序（脚本里的 deploy 动作会做，也可以手动 scp）
.\scripts\deploy-server.ps1 -SkipBuild     # 先用已有产物

# ③ 准备 run.cmd（含环境变量，**不入库**，见第五节）
#    服务的工作目录是 System32，且环境变量不继承 → 必须用 cmd 包装脚本自己 cd + set

# ④ 注册计划任务并启动
ssh <ssh-user>@<server-ip> "schtasks /create /tn ZipperAIQQ /tr 'D:\App\ZipperAIQQ\run.cmd' /sc onstart /ru SYSTEM /f"
ssh <ssh-user>@<server-ip> "schtasks /run /tn ZipperAIQQ"
```

### 必须一起部署的三样东西

| 内容 | 位置 | 缺了会怎样 |
|---|---|---|
| **embedding 模型**（~23MB） | `temp/bge-small-zh-v1.5/` | 启动直接崩：`找不到 embedding 模型` |
| **表情表** | `config/faces.qq.json` | 表情库为空（`表情目录=0 个`），表情发不出去 |
| **人设文件** | `config/persona.md` | 用兜底人设 |
| **server.yaml** | `config/server.yaml` | 退回环境变量（见第四节） |

> 模型和 yaml 都被 `.gitignore` 排除，**不在 publish 产物里** —— 这是最容易漏的一步。

## 四、日常部署

```powershell
# 完整部署：停 → 发布 → 传主程序 → 传附属文件（模型/表情/人设/server.yaml）→ 启动 → 验日志
.\scripts\deploy-server.ps1

# 只改了配置（server.yaml）：重启即可，不重新编译
.\scripts\deploy-server.ps1 -Action restart

# 只停 / 只起
.\scripts\deploy-server.ps1 -Action stop
.\scripts\deploy-server.ps1 -Action start

# 复用上次产物（跳过 dotnet publish）
.\scripts\deploy-server.ps1 -SkipBuild
```

脚本会打印每一步结果，并在启动后**读远端日志尾部**确认
（看到 `消息路由已启动` 才算成功 —— 进程活着不等于接口可用）。

## 五、配置文件 `config/server.yaml`

### 优先级

```
YAML  >  环境变量  >  内置默认值
```

- 让 YAML 压过环境变量：配置文件是"这台机器怎么跑"的正式声明，
  环境变量退化成**部署时的临时覆盖**与**必需项的兜底**。
- 文件不存在 / 解析失败 → 打警告后沿用环境变量（配置写错不该让服务起不来）。
- 可用 `ZIPPER_CONFIG` 指定别的路径。

### 全部字段

```yaml
server:
  httpAddress: 0.0.0.0:5180        # 0.0.0.0 = 允许局域网访问；127.0.0.1 = 仅本机
  httpToken: "<http-token>"         # 非 loopback 时**必须**配，否则拒绝启动
  database: ./data/zipperaiqq.db
  dataProtectionKeys: ./data/keys   # ⚠️ 必须备份，丢了已存的 LLM key 全解不开
  otelConsole: false

napcat:
  wsUrl: "ws://<napcat-host>:<port>"   # 正向 WS，**必须带 token** 否则握手后被 Close
  token: "<napcat-token>"
  selfId: "<bot-qq>"                    # 机器人自己的账号（mention 模式判断 @ 是否指向自己）

llm:
  apiKey: "<llm-api-key>"
  baseUrl: "https://api.deepseek.com"
  model: "deepseek-flash"
  apiKind: Responses                    # Responses | Chat

limits:
  sendIntervalMs: 300      # 同一会话两次发送的最小间隔
  maxConsecutive: 10       # 连发多少条后冷却
  cooldownMs: 10000
  fileMaxBytes: 262144     # 单文件读写上限
  hotWindowMessages: 20    # 上下文热窗条数

access:
  admins: ["<admin-qq>"]   # 客户端管理员（能指挥它动手）
  toolWhitelist: []
  whitelist: []            # 会话名单（qq:g<群号> / qq:p<账号>），模式在客户端切

paths:
  faces: ./config/faces.qq.json
  persona: ./config/persona.md
  workspace: ./workspace
  embeddingModel: ./temp/bge-small-zh-v1.5
```

### 改完怎么生效

```powershell
.\scripts\deploy-server.ps1 -Action restart
```

> **实测**：把 `httpAddress` 从 `0.0.0.0:5180` 改成 `0.0.0.0:5181` → 重启 →
> 5181 可连（`addr=0.0.0.0:5181`）、5180 已关闭。不用改任何启动脚本。

## 六、踩坑记录（都是实际撞到的）

| 坑 | 现象 | 根因 / 解法 |
|---|---|---|
| **服务起不来** | `sc start` 报 1053 | exe 是控制台程序、不实现 SCM → 改用**计划任务** |
| **重启后进程消失** | SSH 一断进程就没了 | Windows OpenSSH 会清理会话子进程 → 改用 `schtasks /run` |
| **远端缺 tar** | 传输失败 | Windows Server 未必带 tar → 用 `scp -r` |
| **启动崩：找不到模型** | `FileNotFoundException: model_quantized.onnx` | 模型被 gitignore，不在 publish 产物里 → 单独传 |
| **表情发成方括号** | `[表情:摊手]` 原样显示 | 表情表没有该名字 → 加同义词映射（详见代码注释） |
| **本地连不上** | 局域网访问超时 | 默认只监听 `127.0.0.1` → 配 `0.0.0.0` + `httpToken` |
| **cmd 脚本乱码** | 命令被截断成 `'ho'` | `.cmd` 必须 **CRLF + GBK(936)**；UTF-8 会被代码页解析错 |
| **PowerShell 多层引号** | `400 Bad Request` / `\.Line 无法识别` | 远程执行改用**脚本文件**或读日志，别硬拼内联命令 |

## 七、敏感信息（**都不入库**）

| 文件 | 内容 | 防护 |
|---|---|---|
| `artifacts/server.yaml` | LLM key / NapCat token / HTTP token | `.gitignore: /artifacts/` |
| `scripts/run-server.local.ps1` | 同上（本机开发用） | `.gitignore: /scripts/*.local.ps1` |
| `scripts/.http-token` | 局域网访问 token | `.gitignore` 显式排除 |
| `scripts/deploy-server.ps1` | 含内网地址 | `.gitignore` 显式排除 |
| `data/keys/` | **密钥环**（加密根） | `.gitignore`；必须单独备份 |

验证方法：

```powershell
git check-ignore -v artifacts/server.yaml scripts/.http-token scripts/deploy-server.ps1
git ls-files | Select-String 'server\.yaml|\.http-token|deploy-server\.ps1'   # 应该没有输出
```

> 目标机上的 `run.cmd` 同样含密钥 —— 它只存在于服务器，从不回传。

## 八、排障清单

```powershell
# 进程在不在
ssh <ssh-user>@<server-ip> "tasklist /fi 'imagename eq ZipperAIQQ.Server.exe' /fo csv /nh"

# 端口在听吗
ssh <ssh-user>@<server-ip> "Get-NetTCPConnection -LocalPort 5180 -State Listen"

# 日志（最有用）
ssh <ssh-user>@<server-ip> "Get-Content 'D:\App\ZipperAIQQ\stdout.log' -Tail 30"

# 接口通不通（需要 token）
Invoke-RestMethod -Uri 'http://<server-ip>:5180/api' -Method Post `
    -ContentType 'application/json' -Headers @{ Authorization = 'Bearer <http-token>' } `
    -Body '{"action":"getStatus"}'
```

**判断"起没起来"的正确姿势**：看日志里有没有 `消息路由已启动`，
而不是只看进程存在 —— 进程活着但初始化失败也是可能的。

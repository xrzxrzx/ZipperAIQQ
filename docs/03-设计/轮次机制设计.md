## 1. 目标与非目标

**目标**

1. 思考进行中到达的新消息可以**引导**当前轮，而不是只能排队等下一轮（R-04）。
2. 一轮可以**跨越空闲期**：无消息时挂起等待，超时收轮（R-10 中/大粒度）。
3. 同一会话**永不并行两轮**；插入不产生第二次独立回答（`问题记录-05` Q5-03）。
4. 挂起/收轮都有审计与指标，状态可解释。

**非目标**

- 不做多轮并行的工具编排（工具仍在轮内串行，由 `FunctionInvokingChatClient` 负责）。
- 不改接缝 A/B/C；纯 Agent 侧 + 会话队列。
- 不做「思考中调工具能提高注意力」的实验结论 —— 那需要对照实验，单独排期。

## 2. 状态机

```
                 ┌──────────── 收到新消息（挂起中）────────────┐
                 ▼                                            │
 Idle ──消息──▶ Running ──无工具调用且模型收尾──▶ Suspended ───┘
   ▲              │  ▲                                │
   │              │  └──steer 注入（下一 turn 开头）────┘
   │              │
   │              ├──达到连续中断上限──▶ 强制跑完（新消息进 followUp）
   │              │
   │              └──超时（挂起上限）──▶ Ended（收轮产物）
   └──────────────── 收轮完成 / 异常 ───────────────────────────┘
```

- **Running**：一次模型调用 + 工具执行（= Pi 的 turn）。轮内可多次 Running。
- **Suspended**：本轮已没有待办工具调用，但允许等待下一条消息续轮；超时收轮。
- **Ended**：收轮产物落库 + 指标；会话回到 Idle。
- 单会话**串行**：进入 Running 前必须拿到会话锁；锁内不允许第二个 Run 启动。

## 3. 双队列（R-04 核心）

新消息按**投递语义**进入一个队列：

| 队列 | 注入时机 | 语义 | 默认场景 |
|---|---|---|---|
| **steer** | 当前 turn 的工具调用**全部完成后**、下一次模型调用前 | 「插句话引导它」 | 私聊（对方就是在跟我说话） |
| **followUp** | 本轮**本会结束**时（模型不再要工具、准备收尾） | 「排队，等它说完再处理」 | 群聊（避免刷屏打断） |

- **拍板（2026-11-06）**：私聊默认 `steer`；群聊**不排队时正常走**，需要排队（运行/挂起中）时
  **由 JEV 判断「引导当前轮」还是「排队」**——与「要不要回话」放在**同一次 judge 调用**里问，不额外多调。
### 3.1 JEV 调用复用（2026-11-06 追加）

现状是「群聊每条消息各判一次」，连发 10 条 = 10 次 judge，而最终只合并成一轮回复 —— 白判 9 次。
K-3 起按三层复用：

1. **批次内只判一次**：群聊 jev 模式在入站时**先不判**，等 600ms 合并窗口结束，用最后一条判一次；
   批里任何一条 @ 了机器人则直接回，不调用 judge。
2. **同消息缓存**：`JudgeVerdictCache`（键 = 会话 + MessageId，TTL 10 分钟），重放/多路径检查不再重复调用。
3. **一次调用回答两件事**（K-3）：judge 的返回扩展为「回复 / 引导 / 排队 / 忽略」，
   「要不要回」与「steer 还是 followUp」共用同一次调用，不新增轮次。

- `steeringMode` / `followUpMode`：`one-at-a-time`（默认，取一条，其余留队列）/ `all`（一次全部注入）。
- **连续中断上限**：默认 2。达到上限后本轮**强制跑完**，新消息只进 followUp，不再注入 steer。
- 私聊是否「直接中断」：由上面默认+配置决定（`turn.steer.private=false` 可关闭）。

**与 R-11 的交互**：steer 注入的内容会改变本轮上下文，长度预算按**最新**注入后的总输入重新计算（预算只约束输出，不变）。

## 4. 收轮产物

收轮（Ended）时必须给出一个**明确产物**，避免「无主的长会话」。候选：

1. **静默收轮**：只落审计（轮次 id、耗时、消息数、工具数、收轮原因）。零额外调用。
2. **总结落库**：额外出一次模型调用，把整轮压成一句「本轮结论」写进审计与记忆。
3. **发给用户**：收轮时主动发一条「先聊到这，有事再叫我」——**默认不做**（像机器人行为）。

默认采用 **1 + 可选 2**（配置 `turn.summary.enabled`，默认关）。

## 5. 定时任务 / 命令在挂起态的处理

| 情形 | 行为 |
|---|---|
| 挂起中收到**命令**（`/status` 等） | **立即执行**，不打断挂起，不并入本轮；执行完继续挂起 |
| 挂起中**定时任务**到点 | 走 `ScheduleAgentExecutor`：作为**独立一轮**排队（受同一会话锁保护），不插入挂起轮 |
| Running 中命令到达 | 与 R-04 同：进 steer 队列；命令本身不注入模型，执行后把结果记进上下文 |

理由：命令是「确定性系统操作」，不该被模型轮次语义吞掉；定时任务是独立轮，避免把「提醒」混进正在聊的话题。

## 6. 幂等与防重复回答

- 每轮有 `TurnId`；steer/followUp 注入都带 `MessageId`，重复投递按 `MessageId` 去重。
- **插入不产生第二次独立回答**：steer 只是追加到下一次模型调用的输入，最终仍只走一次「收尾发送」路径。
- 发送失败/重试：沿用现有 `SendFailureClassifier` 语义，不因轮次机制重发。
- 进程重启：挂起态**不恢复**（重启即收轮），避免「幽灵轮」；`TurnId` 落审计便于核对。

## 7. 指标与审计

| 指标 | 含义 |
|---|---|
| `turn.duration` | 一轮从开始到收轮的毫秒数 |
| `turn.steer` | 被 steer 注入的消息条数 |
| `turn.followup` | 进入 followUp 队列的条数 |
| `turn.interrupted` | 达到连续中断上限、强制跑完的次数 |
| `turn.suspended` | 进入挂起态的轮数（配 `turn.suspend_ms` 值） |
| `reply.interrupted` | 因 steer 导致「原计划回复被改写」的次数（与问题记录 Q5-03 对齐） |

审计（`ConfigAudit` 或新表 `TurnLogs`）：`TurnId / SessionId / 开始 / 收轮 / 原因 / steer 条数 / 工具数 / 产物类型`。

## 8. 配置项（运行时键）

| 键 | 默认 | 说明 |
|---|---|---|
| `turn.suspended.enabled` | `true` | 是否允许挂起等待 |
| `turn.suspend.timeoutMs` | `180000`（3 分钟） | 无消息多久收轮 |
| `turn.steer.maxInterrupts` | `2` | 连续中断上限 |
| `turn.steer.private` | `true` | 私聊默认用 steer（否则 followUp） |
| `turn.steer.group` | `false` | 群聊默认 followUp |
| `turn.steer.mode` / `turn.followup.mode` | `one-at-a-time` | 注入粒度 |
| `turn.summary.enabled` | `false` | 收轮是否生成总结 |

## 9. 分阶段实施

| 步 | 内容 | 验收 |

| K-2 | 会话队列 + `TurnState`（Idle/Running/Suspended/Ended）+ 挂起/超时收轮 | 同会话不并行；挂起超时收轮有审计；不重复触发 |

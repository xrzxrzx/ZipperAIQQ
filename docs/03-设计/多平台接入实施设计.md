### 验收

- 仅 NapCat 时：现有全量测试绿（**回归是硬门槛**）→ ✅ 262 通过
- 两个假通道同时注册：事件都能进 `MessageRouter`，出站不串平台 → ✅ 12 用例覆盖

### 已决事项（原为待确认风险）

| 项 | 结论 | 理由 |
|---|---|---|
| **节流位置** | 仍包在**最外层**（`Throttled(Composite(...))`） | 节流是"同一账号的发送节奏"，与"发到哪个平台"无关；放内层会变成每平台各算一套，等于没限速 |
| **`Platform` 语义** | 复合通道的 `Platform` = **第一个子通道**（今天 = qq），仅供单值消费者兼容 | 多平台下"一个平台"这个概念本身不成立；新代码一律用 `Platforms` / `SelfIdFor` / 按 `ChatRef.Platform` 路由 |
| **`IContactDirectory`** | 复合通道实现它，**转发主平台** | `ChatAgent.cs:573` 靠 `_channel is IContactDirectory` 决定要不要给模型联系人工具；不实现会导致工具在调用时才炸。按平台查询属 S3-C（决策四） |
| **`SelfIdChanged` 的平台归属** | 现阶段所有子通道的事件都往外抛（不带平台信息） | 事件签名是 `Action<string>`，改签名会动公开契约；**S3-E 落地抖音前必须把持久化键改成按平台**（现在是单键 `bot.selfId`，会被后登录的平台覆盖） |

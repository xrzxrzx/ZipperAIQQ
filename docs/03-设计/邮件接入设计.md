## 2. 总体设计

### 2.1 位置：进程内模块（决策一）

```
MailSource : IMessageSource（进程内，IMAP）
   │ ReceiveAsync
   ▼
MessageRouter（Server 编排层）
   ├─ 落库 → MailRepository
   ├─ 摘要 → MailSummaryService ──▶ IChatClientProvider
   ├─ 汇总 → MailDigestService（单封 / 每 N 分钟 / 每日）
   └─ 转发 → IMessageChannel → 主人的 QQ 私聊
```

**不实现 `IMessageChannel`**：邮件只收不发，`SendAsync` 无意义；避免污染接缝 B。

### 2.2 分层与依赖

| 项目 | 依赖 | 变更 |
|---|---|---|
| `ZipperAIQQ.Channel` | 无 | ➕ `IMessageSource`、`IncomingMail` |
| `ZipperAIQQ.Mail`（新增） | Channel | ➕ IMAP 收信 + 账号管理 |
| `ZipperAIQQ.Storage` | Channel | ➕ `MailRepository` + 三张表 |
| `ZipperAIQQ.Server` | 全部 | ➕ 注册 + 摘要服务 + API |
| `ZipperAIQQ.Tests` | 全部 | ➕ 单测 |

> ⚠️ `ZipperAIQQ.Mail` **不依赖 Agent**（通道层不得反向依赖 agent 层）：摘要服务放在 Server，用 `IChatClientProvider` 实现。

### 2.3 输出路径：转发给 QQ 主人（决策九）

邮件**不进入对话回复链路**，而是走「摘要 → 汇总 → 转发」：

| 步骤 | 说明 |
|---|---|
| 1. 摘要 | 单封邮件 → ≤3 句中文要点 +「是否需要处理」 |
| 2. 汇总 | 可配：`immediate`（单封即转）/ `interval`（每 N 分钟合并）/ `daily`（每日汇总） |
| 3. 转发 | 通过 `IMessageChannel.SendAsync` 发到**主人私聊**（`ChatRef { Platform="qq", Type=Private, Id=ownerId }`） |
| 4. 失败处理 | 重试 3 次 → 仍失败记 `failed`，客户端可见原因；**不静默丢** |

- 主人未配置 → 邮件照常落库 + 摘要，但**不转发**，客户端显示「未配置主人」
- 转发内容 = 摘要 + 发件人 + 主题（**不发正文全文**，避免刷屏与泄露）
- 第一期只转 QQ；将来可扩展按平台转发

## 3. 接口定义

### 3.1 `IMessageSource`（新增，`ZipperAIQQ.Channel`）

```csharp
/// <summary>平台无关的「信息源」：只有入站，没有出站。</summary>
/// <remarks>
/// 与 IMessageChannel 的区别：邮件这类源**只收不发**，
/// 硬套 IMessageChannel 会得到一个永远抛异常的 SendAsync。
/// </remarks>
public interface IMessageSource
{
    /// <summary>平台标识，如 "mail"。与 ChatRef.Platform 对应。</summary>
    string Platform { get; }

    /// <summary>持续接收入站事件；实现方负责断线与重连。</summary>
    IAsyncEnumerable<InboundEvent> ReceiveAsync(CancellationToken ct);
}
```

### 3.2 `IncomingMail`（新增模型）

```csharp
public sealed record IncomingMail : InboundEvent
{
    /// <summary>收信账号 ID（MailAccounts.Id）。</summary>
    public required string AccountId { get; init; }

    public required string Subject { get; init; }
    public required string FromAddress { get; init; }
    public string? FromName { get; init; }

    /// <summary>纯文本正文（HTML 由实现层转文本，截断到配置上限）。</summary>
    public required string BodyText { get; init; }

    public bool HasAttachments { get; init; }
}
```

- `EventId` = RFC `Message-Id`（去重键）
- `OccurredAt` = 邮件 `Date` 头（取平台时间，不取 `UtcNow`）
- `Chat` 字段：填 `ChatRef { Platform = "mail", Type = ChatType.Private, Id = $"{AccountId}/{messageId}" }` 仅用于统一事件形状；**不参与对话路由**

### 3.3 `MailSource`（`ZipperAIQQ.Mail`）

```csharp
public sealed class MailSource : IMessageSource, IHostedService
```

职责：

- 启动时从 `MailRepository` 加载**启用**的账号
- 每个账号一个独立 `MailAccountSession`（独立连接、独立重连退避）
- 账号增删改 → 通过 `Changed` 事件热重建（不重启服务）
- **单账号失败不影响其他账号**：异常隔离到会话级

### 3.4 `IMailRepository`（`ZipperAIQQ.Storage`）

```csharp
public interface IMailRepository
{
    Task<bool> AppendAsync(IncomingMail mail, CancellationToken ct = default);
    Task<bool> ExistsAsync(string accountId, string messageId, CancellationToken ct = default);
    Task<IReadOnlyList<StoredMail>> ListAsync(string? accountId, int limit, CancellationToken ct = default);
    Task<StoredMail?> GetAsync(long id, CancellationToken ct = default);
    Task<IReadOnlyList<MailAccount>> LoadAccountsAsync(CancellationToken ct = default);
    Task UpsertAccountAsync(MailAccount account, CancellationToken ct = default);
    Task DeleteAccountAsync(string id, CancellationToken ct = default);
}
```

### 3.5 `IMailSummaryService`（`ZipperAIQQ.Server`）

```csharp
public interface IMailSummaryService
{
    Task<MailSummary> SummarizeAsync(IncomingMail mail, CancellationToken ct = default);
}

public sealed record MailSummary(string Text, bool NeedsAction, string? Error);
```

- 用 `IChatClientProvider` 拿客户端
- **独立 prompt**，不进入任何对话上下文
- 失败重试 3 次（指数退避），仍失败 → `NeedsAction = false` + `Error` 记录，**邮件保留**

### 3.6 `ICredentialProtector`（`ZipperAIQQ.Mail` 内定义）

```csharp
public interface ICredentialProtector
{
    string Protect(string plaintext);
    string? Unprotect(string? cipher);
}
```

> 为什么不在 Mail 里直接依赖 `ISecretProtector`：后者在 `ZipperAIQQ.Server`，Mail 依赖 Server 会倒置。由 Server 注册一个适配器即可。

### 4.4 关于 `ChatType`

**不改 `ChatType` 枚举**。邮件走独立的 `IncomingMail` 事件，不进入对话路由，因此不需要 `ChatType.Mail`。

> 好处：`Messages` 表与对话链路零改动，避免污染；`ChatType` 存 INTEGER，改枚举会牵动数据兼容。

## 5. IMAP 与三家差异

### 5.1 三家配置

| 邮箱 | IMAP 主机 | 认证方式 | 注意点 |
|---|---|---|---|
| **QQ** | `imap.qq.com:993` | 授权码（非登录密码） | 网页端开启 IMAP 服务 |
| **163** | `imap.163.com:993` | 授权码 | **必须发送 IMAP `ID` 命令**，否则服务端报 `Unsafe Login` |
| **Outlook** | `outlook.office365.com:993` | 应用密码 / OAuth2（**待实测**） | 微软在逐步禁用 basic auth，需先验证应用密码是否仍可用 |

> ⚠️ Outlook 的认证方式是**本方案唯一未验证假设**。S3 第一步就是实测：应用密码可用 → 走简单方案；不可用 → OAuth2（设备码或交互式），工作量 +1~2 天。

### 5.2 同步策略

| 项 | 策略 |
|---|---|
| 首次同步 | 只拉最近 **7 天**（可配 `initialDays`），避免拉全量 |
| 增量 | 按 UID 水位（每账号记 `LastUid` / `LastSyncAtMs`） |
| 实时 | 支持 IDLE 就用 IDLE；否则轮询（默认 60s，可配） |
| 去重 | RFC `Message-Id` + 唯一索引 |
| 正文 | HTML 转纯文本（MailKit 的 `TextBody`/`HtmlBody`），截断到 `maxBodyChars`（默认 20000） |

### 5.3 连接管理

- 每账号一个 `ImapClient`，**串行操作**（MailKit 的 client 不保证线程安全）
- 断线 → 指数退避重连（1s → 60s 封顶）
- 账号失效（认证失败）→ **不重试**，标记 `LastError`，等待用户修正
- 优雅关闭：`IHostApplicationLifetime` 里断开所有连接

## 6. 摘要链路

### 6.1 输入

- 主题 + 发件人 + 正文（截断）
- **不传附件、不传 HTML 原文**

### 6.2 Prompt 约束

- 输出 JSON：`{ "summary": "≤3 句中文要点", "needsAction": true|false }`
- 明确要求：不编造、信息不足就说不足
- 判断依据：截止日期 / 发票 / 合同 / 需要回复 / 安全问题

### 6.3 失败与重试

| 情况 | 处理 |
|---|---|
| LLM 429/5xx | 指数退避重试 3 次 |
| LLM 4xx（参数错） | 不重试，标记 failed |
| JSON 解析失败 | 重试 1 次，仍失败标记 failed |
| 全部失败 | 邮件**保留**、摘要状态 `failed`、记录原因 |

### 6.4 并发

- `SemaphoreSlim` 限制并发摘要数（默认 2），避免打爆 DeepSeek 配额

## 8. 验收标准

| # | 标准 | 判定方式 |
|---|---|---|
| 1 | 三家各接 1 个账号，能收到新邮件 | 手工发测试邮件，列表可见 |
| 2 | 邮件到达 → 列表可见 **≤5 分钟** | 计时 |
| 3 | 摘要可用率 **≥16/20** | 抽 20 封人工判定 |
| 4 | 一个账号凭据失效，其余账号继续收信 | 人为改错一个账号密码 |
| 5 | 摘要失败时邮件仍可读，显示失败原因 | 关掉 LLM 端点测试 |
| 6 | 凭据不出现在日志/界面/导出 | 用授权码全文搜索日志与 DB |
| 7 | 重启后不重复收信（去重生效） | 重启前后对比列表 |
| 8 | 断网 10 分钟恢复 → 自动补齐、无重复 | 断网测试 |
| 9 | 摘要能**转发到主人 QQ 私聊**（≤5 分钟） | 配置主人后发测试邮件 |
| 10 | 主人未配置时不静默丢，客户端可见提示 | 清空主人配置测试 |

## 9. 测试策略

| 对象 | 方式 | 必测 |
|---|---|---|
| `MailSource` | 假 `IImapSession`（脚本化产出） | 多账号隔离、单账号异常不拖累其他、重启恢复 |
| `SqliteMailRepository` | 内存 SQLite | 去重（Message-Id）、并发写入、账号删除级联 |
| `MailSummaryService` | 假 `IChatClient` | JSON 解析失败、429 重试、4xx 不重试 |
| 正文截断 | 构造超长正文 | 截断不破坏 UTF-8 |
| 真实 IMAP | **手工**（三家各一封） | 首次同步、增量、断线重连 |

> 原则：**单测不打真实 IMAP / 真实 DeepSeek**（对齐编码规范 §13）。

## 10. 风险与未决

| # | 风险/未决 | 影响 | 缓解 |
|---|---|---|---|
| 1 | **Outlook 认证方式未实测** | 可能阻塞 Outlook 接入 | S3 第一步实测应用密码；不行转 OAuth2 |

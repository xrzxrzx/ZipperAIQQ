# 契约样例（Contract Fixtures）

> **用途**：本项目**不设共享契约项目**，客户端与服务端**各自定义 DTO**。
> 这个目录就是那道安全网 —— **共享数据，不共享代码**。
>
> 📌 本目录**随代码一起开源**（构建与测试都会读它）。更详细的设计说明属于项目内部资料，不随仓库公开 ——
> 所以这里**不写指向内部文档的链接**（那些链接在这个仓库里必然失效）。

## 怎么用

**服务端**与**客户端**各写一个测试，用自家 DTO 去：

1. **反序列化**样例里的 `request` / `response` / `frame` → 断言字段能被正确读入
2. **序列化**回 JSON → 断言字段名与样例**逐字一致**

两边都绿 → **契约事实上一致**。

### 改契约的正确姿势

1. **先改这里的样例文件**
2. 两个测试**同时变红** → 强制你同步两端
3. 别忘了同步更新内部架构方案里 §3.5 那份**人类可读的契约清单**（内部资料，不随仓库公开）

## 断言注意事项

- **只做结构断言**（字段名、类型、必填性）—— **不要断言具体的时间戳 / seq 值**，那些是运行时变量
- ⚠️ **字段名必须逐字比对**：`System.Text.Json` **默认区分大小写** —— 字段名写错会**直接反序列化失败**（比 Newtonsoft 的宽松匹配更安全）。**但序列化方向仍要逐字比对**：属性上的 `[JsonPropertyName]` 写错了，反序列化照样能过，而发出去了对面就认不出
- 样例里的 `_comment` 是**给人看的元数据**；实现侧应当**忽略未知字段**（STJ 默认即忽略未映射属性，无需额外配置）
- 数值字段类型对齐：`seq` / `time` 用 **64 位整数**，避免 JSON 精度坑
- `null` 与"字段缺失"**语义不同**，断言时要区分

## 🔴 硬纪律：样例里**禁止出现真实标识**

**本目录随代码开源，是公开可见的。** 所有标识类字段一律使用**合成占位值**：

| 字段类型 | 用什么 | 禁止 |
|---|---|---|
| `selfUin` / `userId` / `groupId`（QQ 号、群号） | **`1000000000`** 这类明显合成的号 | ❌ **任何真实 QQ 号 / 群号** |
| `nickname` / 群名 | `"示例昵称"` / `"示例群名"` | ❌ 真实昵称 |
| `token` / `apiKey` / 授权相关 | 一律 `null` 或 `""` | ❌ 任何真实凭证 |
| 图片 / 二维码路径 | 不写具体文件名 | ❌ 二维码（**等同账号接管凭证**） |

> **为什么单列一条**：2026-09-22 推之前体检时发现，两处 `selfUin` 写的是**真实 QQ 号** ——
> 而且它躺在**初始提交**里，光补一个修复提交是**没用的**（历史照样查得到），必须**改写提交**才行。
> **契约样例是最容易漏的地方** —— 写的时候只顾着"抓一个真实帧当例子"，就顺手把真号抄进去了。

## 目录

| 文件 | 对应契约 |
|---|---|
| `command-ping.json` | HTTP 命令 `ping`（连通性检查） |
| `command-get-status.json` | HTTP 命令 `getStatus`（含嵌套结构示例） |
| `event-hello.json` | WS 事件 `hello`（连上 `/events` 后服务端下发的第一帧） |
| `event-qq-state.json` | WS 事件 `qq/state`（QQ 通道状态变化） |

> 新增契约按 `command-*.json` / `event-*.json` 命名。
> 事件 `type` 与命令 `action` 的**权威清单**见架构文档 §3.5。

## 统一外壳（所有样例都遵守）

```jsonc
// HTTP 命令：POST /api
{ "action": "<动作名>", "payload": { ... } | null }
→
{ "code": 0, "message": "ok", "data": { ... } | null }

// WebSocket 事件：/events 上的每一帧
{ "type": "<事件类型>", "seq": <int64>, "time": <int64 unix ms>, "data": { ... } | null }
```

- `code = 0` 表示成功，非 0 为业务错误（`message` 带说明）
- `seq` 为**服务端单调递增**，用于客户端判断是否丢帧
- `time` 为 **Unix 毫秒**
